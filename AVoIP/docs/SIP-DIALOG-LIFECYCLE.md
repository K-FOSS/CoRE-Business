# SIP dialog lifecycle and HA teardown

This document describes the carrier-dialog lifecycle after the registrar and
carrier routing tiers were made highly available. It intentionally omits
cluster addresses, client addresses, credentials, and topology tokens.

## Confirmed failure

The carrier Kamailio configuration loaded `dialog.so`, created a dialog for a
managed outbound call, and applied the Admin `max_duration_seconds` value as a
non-resetting local dialog timer. The timeout was therefore measured from the
initial INVITE on the replica that accepted it, independently of FreeSWITCH's
B2BUA channel and independently of SIP session refreshes.

The timeout callback then called `dlg_bye("all")` and deleted the RTPEngine
session. That made a proxy replica originate a carrier BYE while FreeSWITCH
still considered its bridge active. When FreeSWITCH later cleared its own leg,
it sent another BYE and the carrier correctly answered with `481` because the
first proxy-generated BYE had already ended that dialog.

This is distinct from a SIP `Session-Expires` timer. Kamailio's dialog timeout
is an internal module timer; it is not evidence that the SIP session refresher
failed. See the [Kamailio dialog module documentation](https://www.kamailio.org/docs/modules/stable/modules/dialog.html)
and [SIP session timer guidance](https://www.rfc-editor.org/rfc/rfc4028).

## HA correction

Carrier Kamailio no longer creates a process-local dialog timeout for managed
outbound or inbound carrier legs and no longer originates a cleanup BYE for
those legs. FreeSWITCH owns the B2BUA call lifecycle and is the component that
must clear both bridged legs. RTPEngine deletion remains tied to the actual SIP
teardown path, rather than an independent carrier-proxy timer.

Quota admission remains shared. On admission, Kamailio stores a short-lived
direction-specific call-to-quota-key mapping in the shared Redis-compatible
store. `BYE`, failed INVITE transactions, and other release paths resolve that
mapping by Call-ID, so release does not depend on `$dlg_var()` state from the
replica that handled the initial request. The mapping expires automatically if
a call or replica disappears before a normal release.

TOPOS, Record-Route, and transaction routing remain unchanged. They are the
dialog routing mechanisms; Kamailio's local dialog table is not treated as a
shared HA database. PostgreSQL/Redis registration state also does not transfer
a live SIP/TLS connection between replicas.

## TLS identity correction

Before relaying a restored in-dialog TLS request, the carrier route now derives
the TLS SNI from the restored destination host whenever the selected next hop
uses TLS. This keeps certificate verification and hostname selection aligned
after TOPOS restoration. Certificate verification remains enabled; no fallback
to an unverified profile is introduced. See the [Kamailio TLS module documentation](https://www.kamailio.org/docs/modules/stable/modules/tls.html).

## Expected behavior

- A carrier BYE reaches FreeSWITCH and FreeSWITCH clears its corresponding
  WebRTC or SIP leg.
- A client BYE reaches the carrier through the established route and the
  bridged call ends without a proxy-generated duplicate BYE.
- A dialog may traverse a different Kamailio replica. TOPOS and Route headers
  select the established peer; quota cleanup uses shared Call-ID state.
- A replica restart can lose its process-local transaction/dialog cache. It
  cannot preserve a terminated TCP/TLS connection, but it must not create a
  second teardown for a call already handled by another replica.
- Active media is deleted when a real SIP teardown is processed. An abandoned
  quota mapping expires without sending a SIP request from a replica that no
  longer owns the B2BUA call.

## Verification and rollback

The focused render test is `tests/outbound-teardown-render.sh`. It asserts that
the carrier route has shared quota mapping/release, has no outbound
`dlg_set_timeout()` or `dlg_bye()` path, and renders restored-hop SNI handling.

For a live verification, correlate the FreeSWITCH channel IDs, carrier and
internal Call-IDs, Kamailio pod names, and RTPEngine session IDs. Confirm that
the first terminating BYE receives `200`, that FreeSWITCH clears the opposite
leg, and that no later duplicate BYE receives `481`. Also check a carrier-first
hangup and a replica restart during a call.

Rollback is a normal Git/Argo CD rollback to the preceding application
revision. It restores the prior proxy timer behavior and therefore also
restores the premature-timeout risk documented above; do not use rollback as a
substitute for correcting the FreeSWITCH call-lifecycle owner.
